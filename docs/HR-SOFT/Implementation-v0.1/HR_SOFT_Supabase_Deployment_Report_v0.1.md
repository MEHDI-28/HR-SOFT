## ۵. آزمون عملکردی resolver و bootstrap

یک آزمون موقت با کاربر Auth ساختگی در یک subtransaction اجرا شد و در پایان تمام تغییرات آزمون rollback شدند. نتیجه:

1. bootstrap با توکن یک‌بارمصرف توانست Tenant، Company، کاربر داخلی، گروه اولیه، Scope و کاتالوگ مجوز را در محیط آزمایشی بسازد.
2. مجوز org.chart.view با Scope سازمانی مجاز شناخته شد.
3. مجوز sensitive.identity.view برای مدیر اولیه به‌صورت پیش‌فرض رد شد.
4. وجود یک قاعده deny در گروه دیگر، مجوز allow را خنثی کرد؛ یعنی deny-overrides-allow درست عمل کرد.
5. پس از آزمون، Auth users، Tenant، Company و app_users همگی دوباره صفر بودند و توکن همچنان استفاده‌نشده باقی ماند.

این آزمون، آزمون یکپارچه کامل برنامه یا pgTAP نیست؛ منطق SQL و مسیرهای اصلی resolver را بررسی می‌کند.

**بازبینی مجدد در ?? نوامبر ????:** مسیر منفی resolver با JWT آزمایشی فاقد app_users دوباره اجرا شد و نتیجه APP_USER_INACTIVE داد. تابع hr_session_status() نیز برای هویت آزمایشی is_authenticated=true و is_provisioned=false برگرداند. شمار Auth users، Tenant، Company و app_users همچنان صفر است. آزمون مثبت bootstrap در این بازبینی دوباره اجرا نشد.
