# HR-SOFT — معماری رابط کاربری فارسی RTL و نقشه صفحات
## نسخه 2.6

## 1. اصول UI

- زبان پیش‌فرض فارسی و راست‌به‌چپ.
- اعداد، تاریخ‌ها و تقویم در UI قابل تنظیم؛ ذخیره‌سازی تاریخ در DB استاندارد.
- طراحی واکنش‌گرا برای دسکتاپ و تبلت؛ موبایل برای عملیات پرسنلی ضروری.
- فرم‌ها دارای validation سمت کلاینت برای UX و سمت سرور برای امنیت.
- دسترسی به صفحه با permission gate؛ دسترسی به رکورد/فیلد با resolver.
- عدم نمایش عملیات غیرمجاز؛ اما مخفی کردن دکمه جایگزین کنترل سرور نیست.
- وضعیت‌های loading/empty/error/forbidden جدا باشند.
- تأیید عملیات مخرب/حساس و نمایش دلیل/اثر.

## 3. نقشه صفحات

### داشبورد
- کارت‌های aggregate بر اساس scope.
- کارتابل من.
- درخواست‌های ظرفیت معوق (فقط مجاز).
- انتصاب‌های آتی.
- اعلان‌های اخیر.

### مدیریت سامانه
- شرکت‌ها و شرکت‌های زیرمجموعه.
- تنظیمات شرکت.
- سیستم‌ها/زیرسیستم‌ها.
- کاتالوگ کلیدهای مجوز.

### امنیت و کنترل دسترسی
- کاربران
- گروه‌های کاربران
- عضویت گروهی
- مجوزهای گروه
- دامنه داده هر گروه
- دسترسی موقت
- تاریخچه تغییر مجوزها
- مسدودسازی/فعال‌سازی حساب
- کپی مجوزهای گروه (بدون اعضا)

### ساختار سازمانی
- لایه‌های سازمانی
- واحدها و زیرواحدها
- سمت‌ها و ظرفیت
- روابط بین سمت‌ها
- تاریخچه تغییرات

### نمودار سازمانی اجرایی
- فیلتر شرکت و تاریخ
- نمایش واحد/سمت/فرد
- vacancy
- reporting/supervisory/advisory/functional
- نمای جاری و تاریخی
- export کنترل‌شده

### پرسنلی
- فهرست پرونده‌ها
- ایجاد/ویرایش پرونده
- انتساب سمت
- انتصاب‌های آتی
- تاریخچه پرسنلی
- اطلاعات هویتی (مجوز مستقل)
- اطلاعات بانکی (مجوز مستقل)
- مدارک و فایل‌ها (مجوز view/download مستقل)

### گردش کار
- inbox
- جزئیات درخواست
- approve/reject/return
- تاریخچه تصمیم‌ها
- درخواست تغییر ظرفیت
- بازنگری درخواست
- اجرای درخواست
- یادداشت و فایل داخلی مدیران

### اعلانات
- اعلان‌های درون‌برنامه‌ای
- وضعیت خوانده‌شدن
- تنظیم SMS opt-out
- in-app غیرقابل خاموشی

### گزارش‌ها
- کاتالوگ گزارش
- فرم فیلتر
- پیش‌نمایش
- ساخت خروجی
- تاریخچه خروجی‌های کاربر

## 4. الگوی فرم

- عنوان + breadcrumb
- بخش اطلاعات پایه
- فیلدهای وابسته با loading و empty state
- پیام validation نزدیک فیلد
- دکمه ذخیره/انصراف
- برای تاریخچه: timeline read-only
- برای correction: فرم مجزا با reason اجباری و before/after preview
- برای داده حساس: نمایش purpose/reason و ثبت audit

## 5. الگوی جدول

- جست‌وجو و فیلترهای محدود به scope
- pagination سمت سرور
- sort allowlist؛ نام ستون از client مستقیم وارد SQL نشود
- انتخاب چندتایی فقط برای عملیات bulk با authorization per row
- ستون عملیات بر اساس permission؛ server enforcement اجباری
- export با همان query scope

## 6. دسترس‌پذیری و کیفیت
- کنتراست مناسب و keyboard navigation.
- focus state واضح.
- label برای همه فیلدها.
- پیام خطا قابل فهم فارسی.
- جلوگیری از وابستگی صرف به رنگ برای وضعیت.
- نمایش تاریخ/ساعت و timezone روشن.
- تست RTL، اعداد، فونت فارسی، جدول‌های عریض و چاپ PDF.
