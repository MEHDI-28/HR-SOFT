# HR-SOFT — گزارش پیشرفت مرحله ششم
## نسخه 2.4

### انجام شد
1. تعریف قرارداد ورودی/خروجی موتور مجوز مؤثر.
2. تعریف ترتیب ارزیابی هویت، Tenant، سیستم، گروه، مجوز، scope و دسترسی موقت.
3. ثبت semantics مشاهده بدون ستون `can_view` مطابق تصمیم ثبت‌شده.
4. تعریف قاعده deny-first و جمع چندگروهی.
5. تعریف جلوگیری از جعل context با wrapperهای منبع‌محور.
6. تعریف کلیدهای مجوز پیشنهادی برای سامانه، امنیت، سازمان، پرسنل، گردش کار، ظرفیت، فایل، اعلان و گزارش.
7. تعریف قرارداد API و عملیات تراکنشی برای approve/revise/execute/file replacement.
8. تهیه SQL contract skeleton که عمداً تا تکمیل TODOها deny می‌کند.
9. تهیه ماتریس آزمون ACL.

### انجام نشده
- resolver کامل پیاده‌سازی نشده؛ SQL فایل فقط skeleton است.
- RLS policyها به resolver متصل نشده‌اند.
- کلیدهای permission seed نشده‌اند.
- هیچ آزمون ACL اجرا نشده است.
- هیچ SQL در Supabase اجرا نشده است.

### نکته تصمیمی
در مدل موجود `can_view` وجود ندارد. مطابق تصمیم ثبت‌شده کاربر، مشاهده به‌صورت پیش‌فرض در چارچوب permission فعال و scope معتبر است. باید این semantics در تمام APIها و seedها یکسان پیاده شود و نباید در بخشی از UI به‌صورت مجوز آزاد تعبیر شود.

### مرحله بعدی
مرحله هفتم: مدل زمانی (temporal) و ثبت رویدادهای انتساب/تاریخچه، موتور گردش کار، Outbox اعلان‌ها، و سیاست idempotency؛ سپس تکمیل طراحی RLS بر مبنای resolver پیاده‌شده.
