## 2. ریسک‌های باز مهم
1. Resolver هنوز skeleton است و تماماً deny می‌کند؛ هیچ RLS business policy به آن متصل نشده.
2. Migration 0.2 باید با داده واقعی و constraintهای موجود تطبیق داده شود؛ SQL صرفاً proposal است.
3. file owner registry فعلاً فقط capacity_request را پوشش می‌دهد.
4. جدول permissions و group rules نیازمند seed/version strategy و semantics دقیق view است.
5. timezone شرکت و زمان اجرای scheduled هنوز نیازمند تنظیم محصولی است.
6. worker، SMS، exports و scheduler پیاده نشده‌اند.
7. schema واقعی Supabase و drift آن قابل بررسی نبوده است.
8. گزارش‌های Admino فقط عنوان‌شان ثبت شده؛ تعریف دقیق فیلدها/محاسبات تأیید نشده.
9. RPO/RTO، retention و hosting هنوز تعیین نشده‌اند.

## 3. اشکال‌های احتمالی SQL که باید قبل از اجرا بررسی شوند
- وجود `auth` schema و `auth.uid()` در محیط مقصد.
- extensionهای citext و pgcrypto.
- نام constraintهای autogenerated.
- کلیدهای خارجی مرکب و unique indexهای مرجع.
- داده‌های legacy برای `file_objects` و `data_scopes`.
- duplicates پیش از partial unique index ظرفیت.
- تطبیق actor/tenant در audit FKs.
- privileges و owner توابع SECURITY DEFINER.
- triggerهای append-only با نقش‌های maintenance.
- `NOT VALID` constraints و زمان validation.

## 4. قاعده انتشار
تا زمانی که موارد 1 تا 9 بخش ریسک باز بسته نشده‌اند، انتشار production ممنوع است.
